Minimum Doer options (proposals only):

1. If the business confirms current workflow assignee IS the Doer, reuse WorkAssignment.AssignedToId/AssignedToName and workflow assignment synchronization. Validate against the existing unique Users.EmployeeId string and derive name from FirstName/LastName. Preserve reassignment history and enforce one current Meeting assignment in application transactions. No Meeting column is inherently required. Existing arbitrary assignment strings must not be silently treated as validated employees.
2. If Doer is distinct, the minimum independent storage is a nullable Meeting.DoerId string referencing the existing employee identifier convention; derive DoerName from Users. Historical rows need nullable storage with new-write validation, without invented backfill. A separate focused schema change would be required and is not authorized by this investigation's assumptions. A varchar length/FK design must match the actual selected identity column; do not copy an arbitrary length.

CORRECTION: The earlier minutes-linked completion proposal is withdrawn. CompletionMom and CompletionPdfAttachmentId belong to Meeting independently of MeetingMinutes. See MEETING_COMPLETION_PERSISTENCE_PROPOSAL.md for the exact proposed schema and consistency flow.

TAT normalization proposal: use the same PostgreSQL trim/lower expressions for lookup, duplicate checks and the expression unique index; exclude rows with missing/blank classification from eligible rules. Require normalized nonblank inputs for new configuration and reject missing/zero/ambiguous matches when creating tasks. Do not use a nullable raw-column unique index as if it prevented null duplicates. GET historical Meetings should read EaTask.AllottedTatMinutes without live rule resolution.
